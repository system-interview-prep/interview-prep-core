## LIVE — tests that only passed by calling the real provider (29 tests)

Root cause of the "flaky" tests: `.env` holds a real `OPENAI_API_KEY`, `Settings` reads
`.env`, and `tests/conftest.py` blocked the planner, matching and CV-repair model calls
but **not** `src.modules.ai.facade.generate_text`. Any interview test that did not pass
its own `llm_client`/`ai_generator` or patch `generate_text` was grading, probing and
closing with the real model — nondeterministic, slow (the full run went from 188 s to
108 s once blocked) and billed.

Fix applied:

- `tests/conftest.py::_no_live_interview_model` replaces `facade._client` with a
  function that raises, unless `LIVE_LLM_TESTS=1`.
- The 29 tests that then failed with that error carry `@pytest.mark.live_llm(...)` and
  are skipped by default (`pytest_collection_modifyitems`). Run them on purpose with
  `LIVE_LLM_TESTS=1`. Marker registered in `pyproject.toml`.

`test_chat_runtime.py` (15): two_consecutive_give_up…, turn_transition_does_not_repeat_question,
closing_reverse_qna_flow, rt01, rt02, rt03, rt07, rt08, rt09, rt11, rt13, rt16, rt17, rt19,
fast_fail_tech_end_reason_contract.
`test_question_selector.py` (13) and `test_question_bank_eligibility.py` (1): freeze-time
spoken-question generation (`question_selector.py:1642`, `spoken_questions.py:239`).

These are **not** retired: each needs a scripted LLM (Pha 1 fixtures `MockLLM` /
`FakeDecider`); until then they document the intended flow and stay runnable live.
